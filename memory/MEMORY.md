# 记忆增强路线图与状态

M3.5 做了最基础的记忆框架;**M7 把长期记忆重做为 v2**(设计与评测见 `docs/design/M7-记忆强化.md`)。
本文统一用 **名词 → 含义 → 解决什么问题** 三元组,并标注状态与代码位置。

状态图例:🔲 未做  🟡 部分  ✅ 已做  ⛔ 刻意不做(原因见 M7 文档 §3.9)

---

## ① 类型与建模

| 名词 | 含义 | 解决什么问题 | 状态 / 位置 |
| --- | --- | --- | --- |
| 短期/工作记忆 | 当前会话上下文 | 单次任务连贯 | ✅ `short_term.py` |
| 情景记忆 episodic | 发生过的事(调研结论),带日期,只追加、随时间衰减 | 回溯"上次查过什么" | ✅ `schema.py` |
| 语义记忆 semantic | 当前有效的事实(持仓/偏好/关注),**不衰减**,被取代而不删除 | 记住"用户是谁" | ✅ |
| 程序记忆 procedural | 从确定性失败归纳的经验规则,全局共享 | 少撞同一堵墙 | ✅ `procedural.py`(仅离线验证) |
| 来源与可信度 | `source.kind` 区分用户自述 / Agent 结论 | 防记忆投毒、区分可信度 | ✅ |
| 时间有效性 | `as_of`(数据时间)≠ `created_at`(记录时间);失效记 `valid_to/superseded_by` | 金融数据会过期 | ✅ |

## ② 写入侧 —— `write.py` / `extract.py`

| 名词 | 含义 | 解决什么问题 | 状态 |
| --- | --- | --- | --- |
| 写入筛选 + 要点抽取 | LLM 抽结构化候选,空列表=不记;代码层硬上限(≤5 条、情景≤1) | 垃圾入库、整段原文入库 | ✅ |
| 精确冲突消解 | `(user_id, key, subject)` 命中 → 取代旧版本,无需 LLM | 同一事实多版本 | ✅ |
| 模糊冲突消解 | 向量 ≥0.85 → LLM 在 ADD/UPDATE/INVALIDATE/NOOP 里选(无 DELETE) | 同一事实不同说法 | ✅(阈值未标定) |
| 撤销 retract | 清仓→取代为"已清仓"记录;移除关注→作废 | "失效"≠"遗忘"(评测抓出的缺陷) | ✅ |
| 先写新、后失效旧 | `add_many` 成功后才 supersede | 写一半失败不能丢旧值 | ✅ |
| 同步写入 | 写入在用户等待路径上 | 换评测可复现 | 🟡 生产应改后台异步 |
| 遗忘/衰减 | 情景记忆新近度衰减(半衰期 30 天,仅用于重排) | 旧结论权重下降 | 🟡 只衰减权重,不物理淘汰 |

## ③ 读取侧 —— `recall.py` / `tools.py`

| 名词 | 含义 | 解决什么问题 | 状态 |
| --- | --- | --- | --- |
| 画像常驻 | 全部有效语义记忆整份注入,不走检索 | 持仓不会被"衰减"掉;主动服务靠它 | ✅ |
| 目录(渐进式披露) | 一行代码统计"近 90 天调研过 …" | 便宜地告诉模型有什么可深挖 | ✅ |
| 阈值召回 | 低于相关性阈值就不给(默认 0.5) | 拒答能力、防硬塞噪声 | ✅(0.5 基于 9+9 对样本) |
| 三因子重排 | 相关 0.6 + 新近 0.2 + 重要 0.2 | 光相关不够 | 🟡 权重未标定,评测里几乎没被检验 |
| `search_memory` 工具 | 模型按需深挖;无 `user_id` 参数 | 开头注入之外的细节 | ✅ |
| 安全注入 | 记忆块走**用户级**消息,带日期/来源,明示"不是指令" | 持久化提示注入 | ✅ |
| 用户隔离 | `user_id` 关键字必填、无默认值,过滤在接口层 | 跨用户泄漏 | ✅(隔离 0/3→3/3) |
| 反思/巩固 Reflection | 定期把零散记忆归纳成高层洞察 | 记忆太碎 | 🔲 |

## ④ 短期记忆增强 —— `short_term.py`

| 名词 | 含义 | 解决什么问题 | 状态 |
| --- | --- | --- | --- |
| 工具结果裁剪 | 截断过长返回 | 单条撑爆上下文 | ✅ |
| 滑动窗口 + 摘要 compaction | 保留最近 N 条,其余压摘要 | 长会话超窗口 | ✅ |
| 精确 token 预算 / 摘要缓存 | 按 token 控制;摘要只算一次 | 精准、省钱 | 🔲 |
| 上下文换页 MemGPT | 上下文↔外部存储换入换出 | 超大记忆 | 🔲 |

## ⑤ 存储与框架

| 名词 | 含义 | 解决什么问题 | 状态 |
| --- | --- | --- | --- |
| 分库存储 | 情景/语义→Qdrant(`fra_memory_v2`,`type` 区分);程序→Postgres | 各取所长(程序记忆要计数/去重/过期) | ✅ |

## 已知未解决(诚实清单)

- 脏库评测里 v2 的数据是**直接构造**的,没让真实抽取器处理;抽取器的端到端稳定性只被 session 题间接覆盖。
- 程序记忆**没有端到端效果评测**;窗口/过期/激活门槛都是初值。
- 模糊冲突 0.85、情景去重 0.95、重排权重、半衰期均未标定。
- 同步写入与 embedding 延迟未在同地域环境实测(本机 1.3~2.6s,判断为跨境网络,**未验证**)。
- 每轮"提问"也会调一次抽取,是纯开销,可在代码层前置判断。
- 更难的脏库题(≥10 版本、无"更正"字样)与 LLM 裁判宽松度的人工抽查,未做。

## 评测入口

```
python -m eval.memory_offline            # 存储层 25 项(离线)
python -m eval.memory_write_offline      # 写入编排(离线)
python -m eval.memory_read_offline       # 读取侧 + 图节点(离线)
python -m eval.memory_procedural_offline # 程序记忆生命周期(离线,需 Postgres)
python -m eval.memory_calibrate          # 召回阈值标定(一次 embedding 批量调用)
python -m eval.memory_runner --mode off|legacy|v2 [--group clean|dirty|all] [--repeat 3]
```
