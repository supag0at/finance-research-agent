# 记忆增强路线图(留白 / TODO)

当前 M3.5 实现的是"最核心的记忆框架":
- **短期记忆**(`memory/short_term.py`):上下文压缩 = 工具结果裁剪 + 滑动窗口 + LLM 摘要 compaction。
- **长期记忆**(`memory/long_term.py`):跨会话语义记忆,复用 RAG 的 embedding + Qdrant(集合 `fra_memory`),提供 `remember()` / `recall()`。

本文记录后续可加的高阶技巧,统一用 **名词 → 含义 → 解决什么问题** 三元组,
并标注**接入点**与**状态**。等主线走完再挑着做。

## ① 记忆的"类型与建模"

| 名词 | 含义 | 解决什么问题 | 状态 |
| --- | --- | --- | --- |
| 短期/工作记忆 | 当前会话的上下文 | 单次任务的连贯性 | ✅ |
| 长期记忆 | 跨会话持久化 | 让 Agent"记得住"用户与历史 | ✅(基础版) |
| 记忆分型 | 长期再分:情景(episodic 发生的事)/语义(semantic 事实)/程序(procedural 规则技能) | 不同信息需不同存取策略 | 🔲 |

## ② 写入侧(remember)—— 接入点:`memory/long_term.py` remember()

| 名词 | 含义 | 解决什么问题 | 状态 |
| --- | --- | --- | --- |
| 写入筛选 | 用 LLM 判断"这条值不值得记",只存有价值的 | 避免记忆库被垃圾/重复淹没 | 🔲(现在是整段都记) |
| 要点抽取 | 从对话里抽出结构化要点再存,而非存原始长文 | 记忆更干净、检索更准 | 🔲 |
| 更新与冲突消解 | 新信息与旧记忆矛盾时:覆盖/合并/打时间戳(参考 Mem0 的 add-update-delete) | 记忆会过时、会互相矛盾 | 🔲 |
| 遗忘/衰减 | 按时间衰减 + 重要性打分 + 淘汰(LRU 等) | 记忆无限膨胀,成本与噪声上升 | 🔲 |

## ③ 读取侧(recall)—— 接入点:`memory/long_term.py` recall()

| 名词 | 含义 | 解决什么问题 | 状态 |
| --- | --- | --- | --- |
| 相似度检索 | 用向量相似度捞相关记忆 | 基础召回 | ✅ |
| 三因子评分 | 相关性 + 新近性(recency)+ 重要性(importance)加权(参考斯坦福 Generative Agents) | 光"相关"不够,还要看新旧与重要程度 | 🔲 |
| 反思/巩固 Reflection | 定期把零散记忆归纳成更高层洞察 | 原始记忆太碎、缺乏抽象 | 🔲 |

## ④ 短期记忆增强 —— 接入点:`memory/short_term.py`

| 名词 | 含义 | 解决什么问题 | 状态 |
| --- | --- | --- | --- |
| 工具结果裁剪 | 截断过长的工具返回 | 防止单条结果撑爆上下文 | ✅ |
| 滑动窗口 + 摘要 compaction | 保留最近 N 条,其余压成摘要 | 长会话超窗口 | ✅ |
| 精确 token 预算 | 用 tiktoken 等按 token 而非条数/字数控制 | 更精准地贴合上下文上限 | 🔲 |
| 摘要缓存 | 摘要算一次就缓存,别每圈重算 | 降低压缩本身的开销 | 🔲 |
| 上下文换页 MemGPT | 像 OS 分页一样在"上下文↔外部存储"间换入换出记忆(Letta/MemGPT) | 在有限上下文里管理超大记忆 | 🔲 |

## ⑤ 存储与框架

| 名词 | 含义 | 解决什么问题 | 状态 |
| --- | --- | --- | --- |
| 图记忆 Graph Memory | 把记忆存成实体-关系图谱(Zep/Graphiti) | 支持复杂关系查询 | 🔲 |
